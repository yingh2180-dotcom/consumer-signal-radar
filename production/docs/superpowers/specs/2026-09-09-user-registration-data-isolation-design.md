# 用户注册与数据隔离设计

## 变更定位

- 改动标题：用户名密码注册、注册后自动登录、用户数据隔离、公共样本共享。
- 所在模块：登录页、认证接口、数据库、项目及其下游数据接口、模型配置权限。
- 操作类型：新增功能并迁移现有演示数据。
- 不包含：邮箱验证、短信验证、找回密码、第三方登录、团队协作和公网部署。

## 1. 目标

保留现有密码登录能力，在登录页增加“注册账号”。用户使用用户名和密码注册，成功后自动登录。系统内置样本供所有账号使用；每位用户创建的项目、上传评论、分析结果和报告只归本人，并在刷新、退出和重新登录后继续保留。

## 2. 角色与权限

### 2.1 管理员

- 现有本机管理员密码继续可用，避免破坏已有演示入口。
- 管理员可以打开并修改模型 API 配置。
- 管理员可以使用公共样本和管理员自己创建的数据。
- 管理员不会自动取得其他用户私人项目的读取权限。

### 2.2 注册用户

- 使用唯一用户名和密码登录。
- 只能读取、修改和删除自己创建的私人项目及其评论、任务、洞察、报告和评测记录。
- 可以读取并使用系统内置样本。
- 只能看到模型服务是否可用，不能查看或修改 API Key、模型地址和计费开关。

## 3. 数据归属

数据采用两类所有权：

1. `system`：系统内置公共样本，所有已登录账号只读可见。
2. `user`：用户私人数据，仅所有者可见和操作。

当前数据库中的既有演示项目迁移为 `system`，避免注册功能上线后原有面试样本消失。用户从公共样本发起分析时，系统先为该用户创建私人副本，后续任务、洞察和报告归该用户，公共原始样本保持不变。

所有业务数据继续保存在后端 SQLite 数据库和项目数据目录中。前端不把浏览器缓存当作正式存储；页面刷新时重新向后端读取当前账号可见的数据。

## 4. 账号与会话

### 4.1 注册

- 用户名长度 3–32 个字符，只允许中文、英文字母、数字、下划线和短横线；忽略首尾空格，比较时不区分英文字母大小写。
- 密码长度 8–128 个字符。
- 用户名重复时返回明确提示，不泄露其他账号信息。
- 密码使用带随机盐的 `scrypt` 哈希保存，不保存明文。
- 注册成功后创建会话并自动进入工作台。

### 4.2 登录与退出

- 注册用户使用用户名和密码登录。
- 登录页保留“管理员登录”，管理员仍使用本机管理密码。
- 会话 Cookie 保持 `HttpOnly`、`SameSite=Strict`；生产 HTTPS 环境启用 `Secure`。
- 退出登录后删除当前会话。
- 登录失败使用统一错误信息，避免枚举账号。

### 4.3 会话身份

会话记录关联 `user_id` 和角色。每个受保护接口从会话解析当前身份，业务接口不能接受前端传入的所有者身份作为授权依据。

## 5. 后端设计

### 5.1 数据库变化

- 新增 `users` 表：用户编号、规范化用户名、显示用户名、密码哈希、角色、状态、创建时间。
- `sessions` 增加用户编号和角色关联。
- `projects` 增加归属类型和所有者编号。
- 评论、分析任务、洞察、报告和评测通过项目归属继承权限；必要的独立查询仍执行项目所有权校验。
- 数据库迁移必须可重复执行，旧数据库升级后不丢数据。

### 5.2 接口变化

- `POST /api/auth/register`：注册并自动登录。
- `POST /api/auth/login`：注册用户登录。
- `POST /api/auth/admin-login`：兼容现有管理员登录。
- `GET /api/auth/me`：返回当前账号编号、显示用户名和角色，不返回密码信息。
- 所有项目及下游接口加入统一权限查询：公共项目或当前用户所有项目才可读取；只有当前用户所有的私人项目可修改。
- `POST /api/settings` 仅管理员可调用。
- `GET /api/settings` 对普通用户隐藏服务地址和具体配置，只返回模型是否可用、计费调用是否可用和导入上限。

## 6. 前端设计

登录页使用“登录 / 注册”切换：

- 登录表单：用户名、密码、登录按钮，并提供较弱视觉权重的“管理员登录”入口。
- 注册表单：用户名、密码、确认密码、注册并进入按钮。
- 表单显示长度和格式提示；错误就地展示；提交期间禁止重复操作。
- 注册成功后自动进入工作台并加载公共样本与该用户的私人项目。

顶部或设置页显示当前账号名称，并支持退出。普通用户打开模型状态时看不到 API Key 输入框、服务地址和计费配置；管理员保持现有模型配置能力。

公共样本使用“系统样本”标识，并提供“复制到我的项目”操作。公共样本不显示删除或编辑按钮。

## 7. 错误处理

- 用户名重复、格式错误、密码过短返回可理解的中文错误。
- 未登录返回 401，前端回到登录页。
- 已登录但无权访问返回 404，降低通过编号探测他人项目的风险。
- 数据库迁移失败时停止启动并保留原数据库，不以部分迁移状态继续运行。
- 注册或登录失败不创建半成品用户或无主会话。

## 8. 迁移与兼容

1. 启动时在事务中创建新表和字段。
2. 将现有项目标记为公共系统样本。
3. 保留原管理员密码哈希和管理员登录入口。
4. 清理无法关联身份的旧会话，要求重新登录。
5. 迁移完成后校验项目数量、评论数量、任务数量和报告数量与迁移前一致。

## 9. 验收标准

- 新用户可以注册，并在成功后自动进入工作台。
- 用户退出后可以使用相同用户名和密码重新登录。
- 两个测试账号都能看到系统样本，但互相看不到对方的私人项目、评论、任务、洞察和报告。
- 通过直接修改 URL 或请求项目编号也不能访问其他用户数据。
- 刷新、退出和重启服务后，账号和私人数据仍存在。
- 普通用户无法读取或修改模型密钥与服务配置；管理员仍可使用模型配置页。
- 密码和 API Key 不出现在接口响应、日志、前端构建产物或测试快照中。
- 旧演示项目和数据完整迁移为公共样本。
- 全部后端测试、前端生产构建和双账号浏览器流程通过。

## 10. 风险与控制

- 本机演示允许自由注册；公网部署前应增加注册限流、验证码或邀请机制。
- SQLite 适合本项目的单机演示与轻量部署；高并发上线时应迁移到 PostgreSQL。
- 公共样本复制会增加数据量；复制操作应记录来源并避免重复提交。
- 本功能改变数据访问边界，所有项目下游接口必须统一审计，不能只过滤项目列表。
