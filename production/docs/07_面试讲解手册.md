# Consumer Signal Radar 面试讲解手册

## 1. 变更定位

- 新增文件：production/docs/07_面试讲解手册.md
- 文档作用：帮助候选人清楚、诚实地讲出产品价值、AI 设计、工程方案和验证边界。

## 2. 一分钟介绍

“我做了一个美妆消费者洞察 Agent。它解决评论分散、文本口语化、隐性负面难发现和人工整理慢的问题。用户导入评论后，系统会做结构化抽取、主题归并、趋势与机会排序，并让每张正式机会卡关联至少三条原文证据。为了兼顾现场稳定和真实 AI 能力，我设计了离线演示与真实模型双模式，还加入后台任务恢复、证据审核、费用预算和报告导出。目前本机产品闭环、22 项后端测试和前端构建已通过；真实模型 F1、授权真实数据和公网部署仍待验证。”

## 3. 五分钟演示顺序

1. 先讲数据散、非结构化、隐性讨论和洞察滞后。
2. 登录并创建研究项目。
3. 导入合成评论，指出来源状态标签。
4. 运行离线分析，解释后台 Worker 和任务状态。
5. 查看痛点排行与趋势。
6. 打开机会卡，依次讲样本事实、待验证假设、验证建议和结论边界。
7. 打开至少三条原文，演示证据审核。
8. 保存并下载报告。
9. 主动说明真实模型、真实数据、F1 和部署边界。

## 4. 为什么不是普通词云

词云只能告诉我们哪些词出现得多。本系统还回答反馈类型、具体维度、使用场景、变化趋势、严重程度、原文依据和下一步验证建议。

## 5. 三个重点设计

### 5.1 证据优先

每张正式机会卡至少需要三条去重后的负面或混合原文。证据不足就降级为待验证信号。

### 5.2 双模式

离线模式保证现场稳定且零费用；真实模型模式用于验证口语语义理解。两者共享 Schema、任务系统和看板。

### 5.3 后台任务

分析由独立 Worker 执行，并保存租约、心跳和检查点。页面刷新不影响任务查询，Worker 中断后也具备恢复基础。

## 6. 机会分怎样解释

机会分由热度、增长、严重度和未满足程度共同构成，用于比较优先级。它不是市场规模或因果证明。产品经理仍需查看样本和原文，并通过访谈、配方测试或小规模实验验证。

## 7. 技术选择

- React 与 Vite：适合交互看板。
- FastAPI：适合数据校验和 Python 分析。
- SQLite：让单机版无需额外数据库。
- 独立 Worker：避免长任务阻塞网页请求。
- 双模式分析：平衡演示稳定与 AI 真实性。

进入多人高并发环境后，应评估 PostgreSQL、专业任务队列、对象存储、监控和云端密钥管理。

## 8. 高频面试问题

### 数据从哪里来？

当前演示使用明确标记的合成数据。真实业务版应导入公开且获准使用的数据，记录平台、链接、时间和来源审核状态。

### 为什么不用 KMeans 完成一切？

KMeans 只能按向量距离分组，不能保证业务命名、严重度和产品建议正确，还需要结构化字段、证据约束和人工复核。

### 怎样发现不带品牌名的讨论？

真实方案依靠产品特征、成分、使用方式、品类语义和相似表达召回，再由模型和人工复核。当前演示不能证明已覆盖公开平台的水下信息。

### 怎样防止模型胡编？

限制结构化输出，不确定字段允许为空；机会卡必须绑定原文；证据不足不生成正式卡；报告明确样本和方法边界。

### 为什么 F1 还没有结果？

F1 需要独立人工标注的标准答案。当前尚未完成至少 100 条金标和真实模型运行，不能用规则测试或主观体验冒充 F1。

### 如何控制费用？

真实模型默认关闭。系统使用独立预算账本，累计达到 20 元就停止新调用，业务数据恢复不会重置预算。

### 当前算上线了吗？

本机正式版已验证，可用于面试。Docker、域名、HTTPS、正式安全配置和公网运行尚未验收。

### 最大不足是什么？

缺少授权真实样本和独立人工金标，因此业务洞察价值和模型质量还没有最终实证。

## 9. STAR 表达

- Situation：美妆评论分散且口语化，关键词分析遗漏隐性需求。
- Task：短周期内做出从评论到产品机会、且可回溯证据的完整 Demo。
- Action：定义 Schema，设计双模式、后台任务、机会评分、证据审核、预算熔断和报告链路，并完成前后端与测试。
- Result：本机核心流程、前端生产构建和 22 项后端测试通过；真实数据、模型 F1 和部署保留为后续验收。

## 10. 不要夸大

- 不说“已接入十多个平台实时数据”。
- 不说“模型准确率已超过 80%”。
- 不说“已经能预测舆情危机”。
- 不说“机会分就是新品成功概率”。
- 不说“已经完成企业级公网部署”。

## 11. 演示前检查

- [ ] 本机服务和 Worker 正常。
- [ ] 能用本机密码登录。
- [ ] 准备干净的演示项目。
- [ ] 说明合成数据和离线模式。
- [ ] 至少一张机会卡有三条证据。
- [ ] 报告可保存和下载。
- [ ] 不展示 .env 或 API Key。
- [ ] 准备好解释未完成项。

## 12. 结束语

“这个项目的重点是建立从原始评论、结构化理解、主题机会到原文证据和人工复核的决策链路。当前可稳定演示本机闭环，下一阶段用授权真实数据和金标评测验证模型与业务价值。”
