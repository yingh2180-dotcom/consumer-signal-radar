## 5. 还没有完成什么

### 5.1 前端与使用体验（本机核心流程已完成）

生产构建、桌面完整流程和窄屏布局已经通过。后续仍可补充更多浏览器、超大数据、慢网络与长时间运行检查，并对当前较大的 JavaScript 包做按页拆分优化；这些不阻塞本机面试演示。

### 5.2 AI 能力的真实闭环

目前有真实模型调用代码，但没有真实调用成功记录。机会建议仍以通用模板为主，需要补足基于该主题证据的具体解释、适用人群和待验证假设。

当前主题统计以固定分类为主，真实向量聚类用于探索。还要把新主题发现、主题命名和固定统计分类之间的关系在产品中说明清楚，避免把固定标签分类包装成完全自动发现新需求。

### 5.3 真实数据与业务验收

还没有可确认使用条件的真实中文护肤评论集，也没有至少 100 条独立人工标注。不能声称 F1 ≥ 0.8 已实现，不能把合成样例结论当作珀莱雅真实产品问题。

原始需求中的“节省 60% 时间”“提前预警”等是待验证价值假设。面试材料应展示验证办法，而不是写成已取得的业务成果。

### 5.4 部署、恢复与交付材料

启动脚本、数据持久化、备份恢复尚需实际验证。当前机器此前检测为 Windows build 22000，未装 Docker；容器测试路径尚待确认，不能声称部署包已在容器环境跑通。

还需整理新版使用说明、数据说明、评测报告、限制清单、案例报告和真实操作演示。旧版视频不能替代新版演示验收。

## 6. 完成路线图

### 6.1 第一步：补齐前端并打通本地产品

- 工作：补齐样式、修正构建错误、核对页面与接口字段、启动前后端及后台任务进程。
- 依赖：已有代码和本地开发环境，无需 API Key。
- 验收：生产构建成功；实际访问本地网页；完成“登录 → 导入 → 分析 → 审核证据 → 导出”一整条操作。
- 产出：可点击且当次验证过的电脑预览地址、桌面与窄屏截图、问题修复记录。

### 6.2 第二步：验证完整性、恢复能力和证据边界

- 工作：验证跨页面状态、刷新恢复、错误提示、任务中断与重试、重复导入、筛选和下载；实测备份恢复。
- 证据要求：每张机会卡至少 3 条内容去重后的原文；不足时不输出确定结论；报告明确数据来源与分析方式。
- 特别检查：恢复历史业务数据不能回滚已发生的 API 费用记录；无日期数据不能制造增长结论；匿名表达不能强行归属品牌。
- 验收：自动测试继续通过，浏览器流程通过，重启后数据保留，备份能恢复到隔离测试目录。

### 6.3 第三步：完成真实模型小批量联调

- 前置：用户在本机配置 Key，准备有权用于模型处理的评论，确认实际服务可用；不在聊天或报告中记录密钥。
- 工作：先用约 20 条评论验证连接、结构化结果、引用原文、向量返回、耗时和费用记录，再决定是否扩大批量。
- 预算：遵守累计 20 元上限；预算预留是保守估算，不冒充官方账单，联调后核对实际用量。
- 验收：真实请求成功；结果格式正确；证据可回溯；错误可解释、任务可恢复；没有超预算继续调用。
- 产出：真实调用验证记录和具体的模型能力限制。

### 6.4 第四步：补齐机会解释与真实评测

- 工作：让机会说明引用本主题证据，区分事实、推测与需要后续验证的产品假设；完善探索主题的展示和人工命名。
- 数据：先确认来源和使用条件，再准备目标规模 800–1000 条真实评论；数量不足时如实标明样本规模。
- 标注：冻结不少于 100 条人工标注验证集，先约定字段和标注规则，不能直接用模型生成标签充当人工真值。
- 验收：报告逐字段 F1、样本分布、失败案例；目标为关键字段 F1 ≥ 0.8。未达到时修正并重新评测，不能只保留好看的案例。
- 产出：数据来源说明、标注规范、评测结果、带证据的案例报告。

### 6.5 第五步：部署验收与面试交付

- 工作：在确认的兼容环境构建并启动容器，验证健康检查、密码访问、后台任务、持久化与重启；整理配置和恢复说明。
- 若暂时没有兼容环境：先完成本机原生版本，明确标注“容器文件已提供，容器运行未验证”，不把这一项标为完成。
- 面试交付：项目介绍、架构与业务流程、真实评测、失败案例、操作演示视频、启动指南及局限性说明。
- 验收：按文档可复现启动与核心流程；演示与实际功能一致；公网发布仍等待单独授权。

执行依赖：第一步 → 第二步；第三步等待本机模型配置；第四步等待数据和标注，其中机会解释开发可先做；第五步的文档整理可并行，容器实测等待兼容环境。

不承诺固定三天完成最终验收：前端修复可直接推进，但密钥配置、真实数据许可、人工标注和容器环境不是单靠编码就能确定完成时间的事项。
