## 4. 真实数据进入项目的最低条件

正式数据可来自用户有使用权限的导出文件，或使用与展示条件已确认的数据集。导入时记录来源名称、原始链接或导出渠道、获取日期、允许用途和数据类型；不需要收集账号、手机号或其他个人身份信息。

品牌、产品、评论日期仅按原始数据已有证据填写；缺失就保留未知。匿名化数据不反推品牌。没有可比较的真实日期分布时，不输出增长率。至少将合成样本与真实数据分开存储和展示，报告保留来源说明。

## 5. 最小评测执行方案

1. 获得数据后，先按标准化评论内容和近似模板分组去重，再划分开发样本和至少 100 条独立测试评论；同组不跨集合。保留划分清单，避免调整提示词时反复看测试答案。
2. 人工先阅读原文、独立标注反馈类型、维度、情感及必要的原文片段；允许一条评论有多个反馈。模型预标注若被采用，必须记录辅助来源并独立复核，不能把未复核输出算人工真值。
3. 明确字段枚举及“未提及／无法判断”规则；严重度表示评论描述的影响，不能当作医学诊断。场景或成分未出现时，不补造。
4. 分别报告关键字段 F1、每类样本数和失败例，注明是单标签还是多标签及匹配规则。目标 F1 ≥ 0.8 是待验收目标，目前没有实测成绩。
5. 对机会卡另做人工证据支持检查：每个可发布结论至少 3 条去重后相关原文，检查原文是否支持该结论；不足时显示证据不足，不以“有链接”替代“结论受到支持”。
6. 使用真实日期才评估趋势；固定模型、提示词版本，报告处理量、耗时和账单用量。开发联调总预算为用户已确认的 20 元，密钥由用户在本机配置，不写入报告。

## 6. 面试展示表述

在真实数据和评测完成前，可表述“已实现评论导入、分析任务和证据追溯流程；使用明确标记的合成样本展示，真实评测待完成”。不可表述“发现珀莱雅真实痛点”“节省 60% 人工时间”“已实现舆情提前预警”或“F1 已达到 0.8”。

后续只有获准真实数据、独立人工标注、真实模型调用和结果记录都齐备，才形成正式案例报告；公开展示时仍按对应授权条件保留署名、限制或脱敏要求。
